- Relevant log lines

  - The stack trace around [lines 71–76](#L71-L76) shows the failure occurs while importing/processing vite.config.ts.

- Diagnosis
  - Error type: runtime/config error at build-time (thrown while loading vite.config.ts).
  - Cause: vite.config.ts requires a PORT environment variable during config import. Netlify's build environment does not provide PORT by default, so importing the config throws and the build aborts.

- Solutions (choose one or both)
  1. Quick fix in Netlify (no code change)
     - Add a PORT environment variable in your site settings (e.g., 5173).
       - Netlify UI: Site settings → Build & deploy → Environment → Environment variables → Add variable
       - Key: PORT, Value: 5173
     - Re-deploy.
     - Use this if your config legitimately needs a port at build/import time (uncommon).

  2. Recommended fix: make vite.config.ts tolerant of missing PORT
     - Edit artifacts/flight-timetable/vite.config.ts so it does not throw when PORT is missing. Use a default value and only require a port for the dev server, not for build-time import.
     - Example change (replace the part that currently throws when PORT is missing):

```ts
// artifacts/flight-timetable/vite.config.ts
import { defineConfig } from 'vite'

// previously you likely did something like:
// const port = Number(process.env.PORT)
// if (!port) throw new Error('PORT environment variable is required but was not provided.')

// Safer approach:
const DEFAULT_PORT = 5173
const port = Number(process.env.PORT ?? DEFAULT_PORT)

// Only use port for dev server; don't crash at import time
export default defineConfig(({ command }) => {
  if (command === 'serve') {
    return {
      server: { port },
      // other dev options...
    }
  }
  // build config (no port required)
  return {
    // build options...
  }
})
```

     - Commit and push this change. Then re-deploy on Netlify. This prevents the config import from throwing in the build environment.

Notes
- The error occurred during config import (see [line 68](#L68) and [line 70](#L70)), so making the config import safe (not throwing) is the correct long-term solution.
- If you prefer adding an env var in Netlify instead of editing code, use Solution 1; otherwise implement Solution 2 so builds work reliably on Netlify without custom ENV.
